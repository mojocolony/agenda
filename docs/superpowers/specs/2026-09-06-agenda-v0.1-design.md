# Agenda v0.1 Design

**Date:** 2026-09-06
**Status:** Approved

## Goal
Build the permanent v0.1 foundation of a faithful recreation of Savvy Apps' Agenda calendar as a production-quality PWA. v0.1 is a fully usable offline local calendar; Google Calendar synchronization is postponed to v0.2.

## Platform and stack
- React + Vite.
- PWA first, with boundaries that keep a later native implementation feasible.
- iPhone composition is canonical; iPad and desktop preserve the same spatial model rather than becoming conventional desktop calendars.
- Touch gestures are first-class; desktop gets mouse/trackpad equivalents.

## Architecture
Use a neutral Agenda domain model and provider boundary:

`React UI -> Agenda calendar domain -> LocalCalendarProvider -> IndexedDB repository`

For v0.2 this becomes conceptually:

`React UI -> Agenda calendar domain -> GoogleCalendarProvider <-> IndexedDB cache <-> Google Calendar`

Google-specific event objects must not leak into UI components.

## Primary navigation
The horizontal spatial map is:

**Settings | Six Month | Month | Agenda**

- Six Month, Month and Agenda are normally swipeable.
- Settings is beyond the left edge of Six Month and is revealed only by a left-edge-origin drag.
- Swipe right from Settings returns to Six Month.
- A four-position bottom indicator reflects the current horizontal position and tracks movement.
- During a drag, adjacent planes move physically with the gesture.
- Vertical scrolling and horizontal navigation use direction locking.

## Views
### Six Month
Six miniature months in a 2x3 grid, large plus control, today in red, current-week highlight, adjacent-month dates in pale grey, no event-dot clutter.

### Month
Large italic month/year heading, large plus, seven-column grid, red today independent of selection, recessed grey selected date, event-colour dots, dark selected-date divider, and selected-day event area.

The three-circle control toggles a week-selection state within Month. It is not another horizontal plane. In this state the left panel emphasizes the selected date, the centre shows a compact month with a selectable highlighted week, and the right retains the large plus.

### Agenda
A continuous chronological vertical document. Days are content-sized; empty days are compact and busy days expand. Event rows use calendar-colour dots, title, right-aligned time/all-day, optional indented location, and thin day separators. Month boundaries flow naturally.

The floating month label appears while scrolling/navigation, updates at month boundaries, and fades after roughly two seconds of inactivity.

### Settings
Recreate the original sparse Agenda settings language. Initial v0.1 sections include Calendars, Reminders, Event Creation, Date & Time, Sharing, Applications, App Icon Badge, and Sound Effects where applicable to local functionality.

### Event detail and editor
Event detail is a lateral layer that preserves underlying spatial context. The editor uses the reconstructed Agenda visual language: X, italic EVENT heading, checkmark save, large title, visual date selector, time controls, alerts, location and notes. Save commits; cancel discards. Delete uses restrained accidental-tap protection.

## Domain model
Agenda owns normalized calendar and event types.

Calendar: id, name, colour, visible, isDefault, createdAt, updatedAt.

Event: id, calendarId, title, start, end, allDay, location, notes, alerts, createdAt, updatedAt.

No recurrence in v0.1. Attendees/invitations and Google-specific metadata are deferred.

## Persistence and data flow
IndexedDB stores calendars, events, preferences, visibility/default-calendar settings and small persistent UI preferences. React components never access IndexedDB directly.

LocalCalendarProvider supports create/read/update/delete and date-range event queries. All views consume the same provider-backed data so edits appear consistently everywhere.

v0.1 is fully offline. The application shell is cached for offline launch. Browser storage is not treated as backup, so v0.1 includes simple JSON export/import.

## State
Transient UI state stays in React using focused hooks/context rather than Redux: current plane, selected/displayed date, Month mode, open event, editor draft, settings state and gesture state.

## Fidelity rules
The user's still-running original Agenda installation, supplied screenshots and recordings are the primary behavioral reference. Historical sources and Prototype 3 are secondary. Do not modernize established behavior accidentally.

Maintain reference states for Six Month, Month, Month week selector, empty/populated Agenda, month transition, Settings, event detail and editor. Compare at an iPhone-sized viewport.

## Error handling
Storage failures are surfaced concisely and contextually. Successful operations remain visually quiet. Failed writes must never be presented as saved.

## Testing
Automated tests cover date calculations, month boundaries, leap years, all-day events, range queries, visibility, persistence, create/edit/delete and gesture thresholds/direction locking. PWA testing covers install and offline launch on iPhone/iPad Safari and desktop Chrome. Manifest icons must include proper high-resolution assets.

## Explicitly deferred to v0.2+
- Google OAuth and Calendar API integration
- Synchronization/conflict resolution
- Recurrence and recurrence exceptions
- Attendees/invitations
- Google-specific metadata
- Server/backend for Google token handling/webhooks
- Actual device notifications

## v0.1 completion criterion
v0.1 is complete when it can be installed, taken offline, create a calendar and events, persist them across close/reopen, navigate the four-plane interface, display consistent data across views, edit/delete events, export/import local data, and reproduce the approved Agenda interactions reliably.
