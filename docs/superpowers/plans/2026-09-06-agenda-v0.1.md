# Agenda v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a production-quality, installable, offline-first React PWA that faithfully recreates Agenda's core interaction model and provides full local calendar CRUD.

**Architecture:** React components consume an Agenda-owned domain model through `CalendarProvider`; `LocalCalendarProvider` delegates persistence to an IndexedDB repository. Spatial navigation, gestures and view-specific transient state stay in focused hooks/components, isolated from persistence so Google Calendar can replace the provider in v0.2.

**Tech Stack:** React, TypeScript, Vite, Vitest, React Testing Library, fake-indexeddb, IndexedDB, vite-plugin-pwa.

**Spec:** `docs/superpowers/specs/2026-09-06-agenda-v0.1-design.md`

## Global Constraints
- PWA first; preserve portability for a later native implementation.
- iPhone composition is canonical; do not desktopify larger layouts.
- Horizontal map is exactly `Settings | Six Month | Month | Agenda`.
- Settings is entered only by a left-edge-origin drag from Six Month.
- Month week selection is a state inside Month, never a fifth plane.
- Original live Agenda references outrank Prototype 3 when behavior conflicts.
- No recurrence, Google OAuth/API/sync, attendees/invitations, server backend or device notifications in v0.1.
- React components never access IndexedDB directly.
